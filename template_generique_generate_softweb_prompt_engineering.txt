================================================================================
COMPOGlueML — SPÉCIFICATION DE GÉNÉRATION POUR LLM
Version du format : 1.0
Encodage : UTF-8
Rôle : produire un fichier .cgml.json valide à partir d'une description
       fonctionnelle en langage naturel.
================================================================================

================================================================================
1. RÔLE ATTENDU DU LLM
================================================================================

Le LLM reçoit :
  - une description fonctionnelle d'une application (but, écrans, actions)
  - éventuellement des contraintes de style ou d'ergonomie

Le LLM produit :
  - UN SEUL fichier JSON, au format CompoGlueML 1.0
  - contenant : métadonnées, statistiques, une ou plusieurs fenêtres
  - chaque fenêtre embarquant son XML Glade complet ET ses handlers JS
  - le tout directement chargeable dans Composer (composer.html) via
    le bouton "📂 Ouvrir projet", puis exportable en .cgml.html

Aucune autre sortie n'est attendue : ni explication, ni commentaire,
ni Markdown autour du JSON. Le JSON commence par "{" et finit par "}".

================================================================================
2. STRUCTURE RACINE DU FICHIER .cgml.json
================================================================================

{
  "format": "CompoGlueML",
  "formatVersion": "1.0",
  "app": {
    "name":        string,        // nom court, snake_case ou lisible
    "description": string,        // 1 phrase
    "version":     string,        // "0.1.0"
    "author":      string,
    "createdAt":   string,        // ISO 8601
    "updatedAt":   string         // ISO 8601
  },
  "stats": {
    "windowCount":  integer,
    "handlerCount": integer,
    "signalCount":  integer
  },
  "windows": [ Window, ... ]     // 1 à N fenêtres
}

-------------------------------------------------------------------------------
2.1 Objet Window
-------------------------------------------------------------------------------

{
  "id":               string,    // "w1", "w2", ... unique
  "name":             string,    // nom logique du .glade, ex "main.glade"
  "x":                integer,   // position en pixels sur le canevas
  "y":                integer,
  "z":                integer,   // ordre d'empilement, croissant
  "width":            integer,   // largeur forcée de la fenêtre
  "height":           integer,   // hauteur forcée de la fenêtre
  "titlebarVisible":  boolean,   // false = pas de barre de titre
  "xml":              string,    // XML Glade COMPLET, échappé en JSON
  "handlers": {
    "<handler_name>": {
      "widgetId":  string,       // id Glade du widget émetteur
      "gtkSignal": string,       // "clicked" | "changed" | "activate" |
                                 // "toggled" | "state-set"
      "code":      string,       // code JS complet de la fonction
      "modified":  boolean       // true
    },
    ...
  }
}

-------------------------------------------------------------------------------
2.2 Règles impératives
-------------------------------------------------------------------------------

R1. "format" vaut exactement "CompoGlueML".
R2. "formatVersion" vaut exactement "1.0".
R3. Chaque Window possède un "id" unique, croissant : w1, w2, w3...
R4. Chaque Window possède un "xml" Glade valide et complet.
R5. Le XML doit commencer par <?xml version="1.0" encoding="UTF-8"?>.
R6. Le XML doit contenir une unique racine <interface> avec
    <requires lib="gtk+" version="3.24"/>.
R7. Chaque <object class="GtkWindow"> possède un id unique.
R8. Pour chaque <signal name="X" handler="Y"/> présent dans le XML,
    il DOIT exister une entrée "Y" dans "handlers" avec "code" complet.
R9. Le code des handlers est du JavaScript ES5 strictement valide
    (pas de flèches, pas de let/const dans le code exporté — préférer var,
    ou utiliser const/let : les deux fonctionnent côté navigateur, mais
    ES5 évite tout risque de transpilation).
R10. Chaque handler reçoit un paramètre unique "payload" et ne renvoie rien.
R11. Les widgets ciblés dans les handlers doivent exister dans le XML
     de la fenêtre correspondante ou d'une autre fenêtre du projet.
R12. "stats.windowCount" = windows.length
R13. "stats.handlerCount" = nombre de handlers UNIQUES (par nom) tous windows
R14. "stats.signalCount" = somme des handlers déclarés par window
     (les handlers identiques déclarés sur plusieurs widgets comptent une fois
      par widget — c'est la somme brute).

================================================================================
3. API DISPONIBLE DANS LES HANDLERS
================================================================================

Variables globales accessibles dans tout handler :

  Composer.widget(gladeId)
      → retourne l'élément DOM du widget dont l'id Glade = gladeId
      → cherche d'abord dans la fenêtre cliquée, puis dans toutes
      → retourne null si introuvable

  Composer.widgetIn(windowName, gladeId)
      → retourne l'élément DOM du widget ciblé dans la fenêtre
        identifiée par son "name" (ex: "traitement.glade")
      → retourne null si la fenêtre ou le widget est absent

  Composer.widgetsIn(windowName)
      → retourne un objet { gladeId: element } pour la fenêtre donnée

  Composer.setStatus(texte)
      → compositeur : écrit dans la barre de statut
      → export : écrit dans le titre de l'onglet

  Composer.current()
      → retourne le conteneur .cgml-window de la fenêtre cliquée

Le paramètre "payload" contient :

  payload.widgetId    string   id Glade du widget source
  payload.gtkSignal   string   nom du signal GTK
  payload.value       mixed    input.value / checkbox.checked
  payload.element     Element  élément DOM source
  payload.nativeEvent Event    événement DOM natif

4. WIDGETS GTK SUPPORTÉS (liste blanche stricte)
================================================================================

Conteneurs :
  GtkWindow
  GtkBox            (orientation: horizontal | vertical ; spacing)
  GtkGrid           (via <packing><left-attach>/<top-attach>/<width>/<height>)
  GtkFrame          (label en légende)
  GtkScrolledWindow (height-request conseillé)
  GtkNotebook
  GtkStack          (rendu séquentiel)
  GtkEventBox
  GtkExpander       (expanded: True | False)

Contrôles :
  GtkButton
  GtkToggleButton
  GtkCheckButton
  GtkRadioButton    (utiliser <property name="group">id_du_root</property>)
  GtkSwitch
  GtkLabel          (attributs Pango : scale, weight=bold)
  GtkEntry          (editable, placeholder-text, xalign, activate)
  GtkTextView
  GtkComboBoxText   (via <items><item>Texte</item></items>)
  GtkComboBox       (idem GtkComboBoxText)
  GtkMenuButton
  GtkProgressBar    (fraction 0..1)
  GtkSeparator      (orientation)
  GtkImage          (icon-name ou file)
  GtkLinkButton
  GtkSpinner

Widgets NON supportés (à éviter absolument) :
  GtkTreeView, GtkListStore, GtkMenuBar, GtkToolbar, GtkPaned,
  GtkCalendar, GtkDrawingArea, GtkGLArea, GtkSourceView,
  GtkFileChooser, GtkColorChooser, GtkFontChooser.

5. PROPRIÉTÉS XML UTILISABLES
================================================================================

Sur tout widget :
  visible                 True | False
  sensitive               True | False
  can-focus               True | False
  width-request           pixels
  height-request          pixels
  margin-start / margin-end / margin-top / margin-bottom   pixels

Sur GtkBox :
  orientation             horizontal | vertical
  spacing                 pixels
  homogeneous             True | False

Sur GtkGrid :
  column-spacing, row-spacing, column-homogeneous, row-homogeneous

Sur GtkWindow :
  title, default-width, default-height, resizable, window-position

Sur GtkLabel :
  label                   texte (peut contenir emojis)
  xalign                  0 = gauche, 0.5 = centre, 1 = droite
  use-markup              True | False
  <attributes>
      <attribute name="scale"  value="1.4"/>
      <attribute name="weight" value="bold"/>
  </attributes>

Sur GtkEntry :
  placeholder-text, xalign, editable, max-length

Sur GtkProgressBar :
  fraction                0 à 1

Sur GtkExpander :
  label, expanded         True | False

Sur GtkRadioButton :
  label, active, group    (group = id du GtkRadioButton racine)

Sur GtkComboBoxText :
  <items>
      <item>Texte 1</item>
      <item>Texte 2</item>
  </items>

Signaux XML autorisés :
  <signal name="clicked"   handler="..." swapped="no"/>
  <signal name="changed"   handler="..." swapped="no"/>
  <signal name="activate"  handler="..." swapped="no"/>
  <signal name="toggled"   handler="..." swapped="no"/>
  <signal name="state-set" handler="..." swapped="no"/>

================================================================================
7. TEMPLATE — HANDLER DE BASE
================================================================================

Chaque handler suit STRICTEMENT ce patron :

function <handler_name>(payload) {
  <corps>
}

Règles :
  - Un seul paramètre : payload
  - Aucun return (sauf early return pour garde)
  - Toujours tester les widgets retournés avant usage
  - Utiliser Composer.widget / Composer.widgetIn / Composer.setStatus
  - Le style des lignes dynamiques est en inline via .style.cssText

8. BIBLIOTHÈQUE DE SNIPPETS DE HANDLERS

-------------------------------------------------------------------------------
8.1 Ajouter une ligne dans une liste
-------------------------------------------------------------------------------
function on_add_clicked(payload) {
  var input = Composer.widget('input_field');
  var list  = Composer.widget('output_list');
  if (!input || !list) return;
  var v = input.value.trim();
  if (!v) return;
  var row = document.createElement('div');
  row.style.cssText = 'padding:4px 8px;background:#f8f8f8;border-radius:4px;font-size:12px';
  row.textContent = v;
  list.appendChild(row);
  input.value = '';
  input.focus();
}

-------------------------------------------------------------------------------
8.2 Vider une liste
-------------------------------------------------------------------------------
function on_clear_clicked(payload) {
  var list = Composer.widget('output_list');
  if (list) list.innerHTML = '';
}

-------------------------------------------------------------------------------
8.3 Lire le radio coché
-------------------------------------------------------------------------------
function on_op_changed(payload) {
  var ids = ['op_a', 'op_b', 'op_c'];
  var current = '?';
  for (var i = 0; i < ids.length; i++) {
    var wrap = Composer.widget(ids[i]);
    if (!wrap) continue;
    var input = wrap.querySelector('input[type="radio"]');
    if (input && input.checked) { current = ids[i]; break; }
  }
  Composer.setStatus('Choix : ' + current);
}

-------------------------------------------------------------------------------
8.4 Lire le combo sélectionné
-------------------------------------------------------------------------------
function on_combo_changed(payload) {
  var sel = Composer.widget('my_combo');
  if (!sel) return;
  Composer.setStatus('Valeur : ' + sel.value);
}

-------------------------------------------------------------------------------
8.5 Transférer des données entre deux fenêtres
-------------------------------------------------------------------------------
function on_send_clicked(payload) {
  var src = Composer.widget('source_list');
  var dst = Composer.widgetIn('cible.glade', 'target_list');
  if (!src || !dst) {
    Composer.setStatus('Fenêtre cible absente');
    return;
  }
  dst.innerHTML = '';
  var rows = Array.prototype.slice.call(src.children);
  for (var i = 0; i < rows.length; i++) {
    var copy = rows[i].cloneNode(true);
    dst.appendChild(copy);
  }
}

-------------------------------------------------------------------------------
8.6 Calcul (somme, moyenne, min, max)
-------------------------------------------------------------------------------
function on_compute_clicked(payload) {
  var list = Composer.widget('data_list');
  var result = Composer.widget('result_label');
  if (!list || !result) return;
  var values = [];
  var rows = Array.prototype.slice.call(list.children);
  for (var i = 0; i < rows.length; i++) {
    var v = parseFloat(rows[i].dataset.value);
    if (!isNaN(v)) values.push(v);
  }
  if (!values.length) { result.textContent = '—'; return; }
  var sum = 0;
  for (var j = 0; j < values.length; j++) sum += values[j];
  var avg = sum / values.length;
  result.textContent = 'Somme : ' + sum + ' — Moyenne : ' + avg.toFixed(2);
}

-------------------------------------------------------------------------------
8.7 Afficher / masquer un panneau
-------------------------------------------------------------------------------
function on_toggle_clicked(payload) {
  var panel = Composer.widget('side_panel');
  if (!panel) return;
  var hidden = panel.style.display === 'none';
  panel.style.display = hidden ? '' : 'none';
}

-------------------------------------------------------------------------------
8.8 Incrémenter un compteur
-------------------------------------------------------------------------------
function on_inc_clicked(payload) {
  var lbl = Composer.widget('counter_label');
  if (!lbl) return;
  var n = parseInt(lbl.textContent, 10) || 0;
  lbl.textContent = String(n + 1);
}

-------------------------------------------------------------------------------
8.9 Horodatage dans un journal
-------------------------------------------------------------------------------
function on_log_clicked(payload) {
  var box = Composer.widget('log_box');
  if (!box) return;
  var entry = document.createElement('div');
  entry.style.cssText = 'font-size:11px;color:#666';
  entry.textContent = '[' + new Date().toLocaleTimeString() + '] action';
  box.appendChild(entry);
  box.scrollTop = box.scrollHeight;
}

-------------------------------------------------------------------------------
8.10 Confirmation simple
-------------------------------------------------------------------------------
function on_delete_clicked(payload) {
  if (!confirm('Confirmer la suppression ?')) return;
  var list = Composer.widget('items_list');
  if (list) list.innerHTML = '';
  Composer.setStatus('Supprimé');
}

================================================================================
10. RÈGLES D'ERGONOMIE À RESPECTER
================================================================================

E1.  Chaque fenêtre a un titre clair avec un emoji en tête.
E2.  Chaque fenêtre utilise une GtkBox verticale racine avec spacing 8-10.
E3.  Marges extérieures : 14 px de chaque côté.
E4.  Zones regroupées dans des GtkFrame avec label explicite.
E5.  Boutons d'action en bas de fenêtre, hauteur 34-38 px.
E6.  Labels de résultat en gros (attribut scale >= 1.4, weight = bold).
E7.  Champs de saisie avec placeholder-text explicite.
E8.  Listes dans un GtkScrolledWindow avec height-request 130-240 px.
E9.  Un champ status en haut à droite (compteur ou état).
E10. Aucun texte en anglais dans l'interface : tout en français.

================================================================================
11. CONTRAINTES STRICTES (à ne jamais violer)
================================================================================

N1.  Ne jamais générer de GtkTreeView, GtkMenuBar, GtkToolbar, GtkPaned.
N2.  Ne jamais écrire de handler qui référence un widget inexistant.
N3.  Ne jamais omettre le handler d'un <signal> présent dans le XML.
N4.  Ne jamais produire de JSON avec des virgules finales.
N5.  Ne jamais utiliser d'accolades simples dans les chaînes JSON : utiliser \" pour les guillemets internes.
N6.  Ne jamais insérer de commentaire /* */ ou // dans le XML.
N7.  Ne jamais nommer deux fenêtres avec le même "id".
N8.  Ne jamais nommer deux handlers identiques DANS la même fenêtre.
      (Un même handler peut être partagé entre widgets d'une même fenêtre,
       comme on_op_changed sur plusieurs radios.)
N9.  Ne jamais introduire de dépendance externe (jQuery, axios, etc.).
N10. Ne jamais utiliser fetch / XMLHttpRequest : tout est local.
N11. Ne jamais utiliser localStorage : l'export doit rester sandbox-safe.
N12. Ne jamais écrire dans document.body : tout dans les widgets ciblés.

12. FORMAT DE SORTIE
================================================================================

Sortie attendue : un unique objet JSON, sans texte avant ni après.
Encodage : ASCII strict dans le JSON lui-même, mais les chaînes
peuvent contenir des caractères UTF-8 (emojis, accents).
Le JSON doit être indenté avec 2 espaces et rester lisible.
